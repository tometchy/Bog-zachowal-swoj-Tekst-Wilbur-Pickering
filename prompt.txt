Tak — to wygląda na **regresję instalatora ACP po aktualizacji Ridera**, szczególnie widoczną na Twoim ARM64. Rider ma `@openai/codex`, ale npm nie dociągnął platformowej paczki `@openai/codex-linux-arm64`. Codex rzeczywiście publikuje osobną paczkę dla Linux ARM64 jako optional dependency. ([UNPKG][1])

Nie zaczynałbym od zalecanego przez komunikat:

```bash
npm install -g @openai/codex@latest
```

bo Rider odpala **swoją kopię** z:

```text
~/.cache/JetBrains/Rider2026.2/acp-agents/codex-acp/1.6.2/
```

więc globalna instalacja może niczego nie zmienić.

### Najpierw naprawmy dokładnie tę kopię Ridera

Zamknij Ridera i wykonaj:

```bash
BASE="$HOME/.cache/JetBrains/Rider2026.2/acp-agents/codex-acp/1.6.2"

V=$(node -p "require('$BASE/node_modules/@openai/codex/package.json').version")

echo "Codex version: $V"

cd "$BASE" && \
npm install --no-save "@openai/codex-linux-arm64@npm:@openai/codex@${V}-linux-arm64"
```

To **nie instaluje nowszej, przypadkowej wersji** Codexa. Odczytuje wersję, którą Rider już ma, np. `0.145.0`, i dokłada dokładnie odpowiadające jej binarium ARM64:

```text
@openai/codex-linux-arm64
    → @openai/codex@0.145.0-linux-arm64
```

Właśnie taki mechanizm oficjalnie stosuje Codex. ([GitHub][2])

Potem sprawdź:

```bash
ls -ld "$BASE/node_modules/@openai/codex-linux-arm64"
```

i:

```bash
node "$BASE/node_modules/@openai/codex/bin/codex.js" --version
```

Jeżeli dostaniesz np.:

```text
codex-cli 0.xxx.x
```

to uruchom Ridera i Codex powinien wstać.

### Jeśli `npm` nie istnieje w Twoim shellu

Nie instaluj na razie Node'a do systemu. Rider już ma własnego Node `24.13.0`. Znajdziemy jego npm:

```bash
find "$HOME/.cache/JetBrains/Rider2026.2/acp-agents/.runtimes/node" \
  -type f \( -name npm -o -name npm-cli.js \) -print
```

Wklej mi wynik i użyjemy dokładnie runtime'u Ridera.

### Dlaczego podejrzewam npm/Ridera

To nie jest egzotyczny błąd samego ARM. OpenAI miało już zgłoszenia, w których npm instalował główną paczkę `@openai/codex`, ale pomijał właściwą platformową optional dependency, po czym launcher kończył się dokładnie komunikatem:

> `Missing optional dependency @openai/codex-linux-*`

Maintainer Codexa wskazywał wprost na możliwą regresję npm w obsłudze tych optional dependencies. ([GitHub][3])

Dodatkowo JetBrains miał już regresje po aktualizacji IDE dotyczące instalowania `codex-acp`. ([YouTrack][4])

**Zacząłbym od powyższych dwóch poleceń.** Jeśli instalacja wywali błąd albo `codex.js --version` nadal nie ruszy, wklej cały output — wtedy zobaczymy, czy Rider 2026.2 ma jeszcze drugi problem z ACP na aarch64.
